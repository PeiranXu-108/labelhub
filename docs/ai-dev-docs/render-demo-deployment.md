# Render Demo Deployment

This document describes how to publish the LabelHub MVP as a publicly
reachable Render demo environment.

## Current Status

- Repository-side deployment config: `render.yaml`.
- Target platform: Render Blueprint.
- Default frontend URL: `https://labelhub-demo-frontend.onrender.com`.
- Default API URL: `https://labelhub-demo-api.onrender.com`.
- Cloud creation status: pending manual Render Dashboard creation.

If Render assigns different service URLs because of a name conflict, update:

- `VITE_API_BASE_URL` on `labelhub-demo-frontend`.
- `LABELHUB_CORS_ORIGINS` on `labelhub-demo-api`.

Then redeploy both services.

## Architecture

The Blueprint creates:

- `labelhub-demo-api`: Docker web service running FastAPI.
- `labelhub-demo-worker`: Docker background worker running Celery.
- `labelhub-demo-frontend`: static React/Vite frontend.
- `labelhub-demo-db`: Render Postgres.
- `labelhub-demo-redis`: Render Key Value used as the Celery broker.

The API starts with:

```bash
alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
```

The worker starts with:

```bash
celery -A app.workers.celery_app.celery_app worker --loglevel=info
```

## Required Secrets And Environment

`render.yaml` injects database and Redis URLs from Render-managed services.
It also generates `LABELHUB_JWT_SECRET_KEY` for the API.

The demo intentionally leaves `LABELHUB_LLM_API_KEY` blank. In that mode:

- AI review follows the controlled missing-credentials path.
- Field-level assist returns the controlled provider-unavailable response.
- No live model request is made.

To enable live AI later, add the provider key manually in Render for both:

- `labelhub-demo-api`
- `labelhub-demo-worker`

Do not commit real API keys. If a real LLM key was ever written to
`.env.example`, rotate that key in the provider dashboard before using the
demo.

## Create The Render Blueprint

1. Commit and push the repository changes containing `render.yaml`.
2. Open the Render Dashboard.
3. Create a new Blueprint.
4. Connect the GitHub repository `PeiranXu-108/labelhub`.
5. Select branch `main`.
6. Confirm the Blueprint resources:
   - `labelhub-demo-api`
   - `labelhub-demo-worker`
   - `labelhub-demo-frontend`
   - `labelhub-demo-db`
   - `labelhub-demo-redis`
7. Start the initial deploy.
8. Wait for API, worker, frontend, Postgres, and Redis to finish deploying.

## Verify Deployment

Check the API health endpoint:

```bash
curl https://labelhub-demo-api.onrender.com/health
```

Expected response:

```json
{"status":"ok"}
```

Open the frontend:

```text
https://labelhub-demo-frontend.onrender.com/login
```

If the login page loads but requests fail in the browser, check:

- The frontend service `VITE_API_BASE_URL` matches the actual API URL.
- The API service `LABELHUB_CORS_ORIGINS` is a JSON array containing the actual
  frontend URL, for example:

```text
["https://labelhub-demo-frontend.onrender.com"]
```

## Seed Demo Users

After the API deployment completes and migrations have run, open a shell or
one-off job for the `labelhub-demo-api` service and run:

```bash
python scripts/seed_e2e_data.py demo-users
```

Demo credentials:

- Owner: `owner@example.com` / `LabelHubOwner123!`
- Labeler: `labeler@example.com` / `LabelHubLabeler123!`
- Reviewer: `reviewer@example.com` / `LabelHubReviewer123!`

Verify each account can log in from:

```text
https://labelhub-demo-frontend.onrender.com/login
```

## Demo Flow

Use `docs/demo-script.md` for the product walkthrough:

1. Owner creates a task, imports data, publishes a template, and publishes the
   task.
2. Labeler claims the task and submits an annotation.
3. Worker records the missing-key AI fallback unless live AI credentials are
   configured.
4. Reviewer approves or returns the submission.
5. Owner exports approved data.

## Known Render Demo Limitations

- Render free Postgres databases expire on Render's free-plan schedule. Do not
  treat the demo database as durable production storage.
- `labelhub-demo-api` and `labelhub-demo-worker` run as separate services and
  do not share a filesystem. Export files generated by the worker may not be
  downloadable through the API until export storage is moved to object storage
  or another shared storage design.
- Upload and export storage still use local filesystem paths in this MVP.
- The demo uses deterministic demo credentials and is not a production identity
  setup.
- The frontend is a static production build, but broader production hardening
  such as custom domains, SSO, DLP, retention policy, and object storage is out
  of scope for this demo environment.

## Redeploy And Rollback

Redeploy from Render Dashboard:

1. Open the target service.
2. Select **Manual Deploy**.
3. Choose **Deploy latest commit**.

Rollback from Render Dashboard:

1. Open the target service.
2. Open **Deploys**.
3. Select a previous successful deploy.
4. Choose **Rollback**.

If the API fails after a schema change, inspect the API logs first because
`alembic upgrade head` runs before Uvicorn starts.
